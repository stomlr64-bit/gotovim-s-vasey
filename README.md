## Как открыть на компьютере

Дважды нажать `start-preview.cmd`. Он использует уже имеющийся Node.js из Codex или системный Node.js, запускает сервер только на этом компьютере и открывает браузер. Ничего не устанавливает. Пока открыт сайт, оставь окно просмотра работающим; закрытие окна останавливает сервер.

Если открыть `index.html` двойным щелчком, браузер может запретить загрузку JSON. Это ограничение локальных файлов. Через локальный сервер и GitHub Pages загрузка работает.

## Как добавить новый рецепт без кода

1. Сделать копию всей папки сайта, чтобы сохранить предыдущий вариант.
2. Открыть `tools/recipe-editor.html` двойным щелчком. Эта форма работает и без сервера.
3. Выбрать `data/recipes.json` из последней копии сайта. Форма покажет количество существующих рецептов.
4. Ввести название, категорию, ингредиенты и шаги — по одному пункту на строку. Выбрать картинку. При желании добавить время, описание/комментарий, совет, слова для поиска и отдельный файл карточки PNG/JPG/WebP/PDF/TXT.
5. Нажать «Скачать дополнение ZIP». Форма сохраняет прежние рецепты и добавляет новый первым. Можно добавить несколько подряд: последний ZIP содержит все новые материалы текущего сеанса.
6. Распаковать последний ZIP и перенести его папки `data` и `assets` в подготовленную копию сайта, согласившись на замену `data/recipes.json`. Это дополнение, а не полный сайт: остальные файлы сохраняются.
7. Открыть копию через `start-preview.cmd` и проверить рецепт. При последующем добавлении снова выбрать уже обновлённый JSON, чтобы не потерять предыдущие дополнения.

Форма не публикует и не меняет файлы самостоятельно. Для появления новых рецептов в интернете обновлённые файлы нужно отдельно загрузить в тот же GitHub-репозиторий. Твою фотографию в шапке форма не затрагивает. Можно также передать Васе название, картинку, ингредиенты, шаги, комментарий и карточку — для подготовки очередного дополнения.

## Будущая публикация GitHub Pages

Папка готова как статический сайт. В корне будущего репозитория должны оказаться `index.html`, `data`, `assets` и `.nojekyll`, а не внешняя папка-обёртка. Затем в Settings → Pages выбирается публикация из ветки с этими файлами, каталог `/ (root)`. Сборка приложения и Netlify не требуются.

Относительные пути проверены и для адреса вида `https://имя.github.io/имя-репозитория/`. Адреса будущего репозитория и сайта пока нет: репозиторий не создавался, публикация не выполнялась.

Сайт GitHub Pages получит собственный адрес; существующий адрес Netlify автоматически к нему не привяжется. Текущая версия Netlify остаётся самостоятельной рабочей версией.

Официальное описание: https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages
